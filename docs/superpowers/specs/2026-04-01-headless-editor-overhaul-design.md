# Headless Editor Overhaul

**Created**: 2026-04-01
**Status**: In Progress

## Overview

A comprehensive polish and feature enhancement pass on the headless editor — the native writing interface that syncs with NovelAI's ProseMirror editor. The goal is full parity with NovelAI's native interface plus meaningful improvements: inline scene image embedding, switchable presentation themes, a fully redesigned lorebook manager, a dedicated preamble/instructions panel, and a restructured memory system.

**Implementation strategy: Architecture First.** The image embedding system and theme engine are built first since both touch the editor's core sync logic. Everything else builds on top.

---

## Section 1: Image Embedding

### Concept
Scene images generated by the app can be embedded inline in the story text, coexisting with prose in magazine or graphic novel style. Images live as `<figure contenteditable="false">` nodes inside the contenteditable editor — real DOM nodes the editor navigates around but cannot type into. Before syncing to NovelAI, all figures are stripped and their positions recorded. After syncing from NovelAI, figures are re-injected at the same positions. NovelAI's story text stays clean; the headless editor shows the illustrated view.

### Storage
New `story_images` SQLite table:

| Column | Type | Description |
|---|---|---|
| `id` | TEXT PK | Generated ID |
| `story_id` | TEXT | FK to stories |
| `image_id` | TEXT | FK to media_items |
| `paragraph_index` | INTEGER | 0-based paragraph anchor; recomputed on each editor save |
| `layout_mode` | TEXT | `break` / `float` / `margin` / `bleed` |
| `float_side` | TEXT | `left` / `right` (float mode only) |
| `caption` | TEXT | Optional caption text |

### Layout Modes
- **Break** — Full column width, acts as a visual scene break between paragraphs
- **Float** — Floats left or right with text wrapping around it, magazine style
- **Margin** — Fixed-width column to the right; text stays in its lane
- **Bleed** — Full editor width edge-to-edge, with optional text overlay at the bottom

### Placement
- **Auto:** When `image:generated` fires, inject a figure immediately after the current paragraph boundary. Defaults to `break` layout for first image, then last-used mode.
- **Manual:** Drag from image gallery panel, or use command palette ("Insert image here") to pick from recent generations.

### Controls
- **Hover** → compact toolbar: 4 layout mode icons (active one highlighted in accent), swap button, remove button, settings button
- **Settings button** → popover panel: caption field, float side toggle (float mode only), swap-from-gallery picker
- **Break layout only** → inline handle strip below image for visual sizing feedback and layout switching

### New Files
- `app/renderer/modules/headless-image-embed.js` — image injection, strip/restore on sync, hover controls, popover
- `app/db.js` — add `story_images` table, CRUD helpers
- `app/main.js` — IPC handlers: `story-images:get`, `story-images:set`, `story-images:remove`
- `app/preload.js` — bridge methods for above

### Modified Files
- `app/renderer/modules/headless-editor.js` — `syncToWebview()` strips figures before push; `syncFromWebview()` re-injects figures after pull
- `app/renderer/modules/headless-sync.js` — wire `headless-image-embed` into init sequence
- `app/renderer/styles/main.css` — figure layout styles for all four modes per theme

## Section 2: Theme Engine

### Concept
Three switchable presentation modes selected via a `M / E / G` toggle in the editor toolbar. Stored per-story in `story_settings.editorTheme`. Defaults to Manuscript.

### Modes

**Manuscript** (default)
- Font: `'Courier New', monospace`
- Line height: 1.9
- First-line indent: `text-indent: 2em`
- Scene breaks: `# # #` rendered as styled div
- Chapter word count shown in status bar
- AI text: dotted underline only — minimal noise

**Editorial**
- Font: `Georgia, serif`
- Line height: 1.8
- Centered chapter headings
- Scene breaks: `✦ ✦ ✦` ornamental divs
- AI text: subtle left border + cool blue-tint background

**Graphic Novel**
- Font: System sans-serif
- Line height: 1.7
- Scene headers: accent-colour left-border tags (`SCENE 3 · The Corridor`)
- Scene breaks: gradient line
- AI text: faint violet tint with thin border

### Scene Break Detection
Lines containing only `---`, `* * *`, `# # #`, or `✦ ✦ ✦` are converted to theme-styled `<div class="scene-break">` elements at render time. Underlying text is unchanged.

### Image Integration
Images adopt per-theme framing:
- Manuscript: thin border frame
- Editorial: subtle drop shadow
- Graphic Novel: full-bleed treatment as default

### New Files
- `app/renderer/modules/headless-theme.js` — theme switching, scene break detection, toolbar toggle wiring

### Modified Files
- `app/renderer/styles/main.css` — `.theme-manuscript`, `.theme-editorial`, `.theme-graphic-novel` classes on editor container
- `app/renderer/modules/headless-editor.js` — load/save `editorTheme` from `story_settings`
- `app/renderer/index.html` — `M / E / G` toggle buttons in toolbar

## Section 3: Lorebook Manager

### Concept
The existing lore panel is replaced with a proper two-pane manager providing full NovelAI lorebook parity plus bulk operations. Panel remains `.wide` (700px).

### Left Pane — Category Tree (200px)
- Collapsible categories with entry counts matching NovelAI's actual categories
- Drag-to-reorder categories
- `+ New Category` at bottom
- Search input filters entries across all categories; non-matching categories collapse
- **Bulk mode toggle** — activates checkboxes on each entry. Bulk action bar at bottom: Move to Category, Delete, Export (JSON)

### Right Pane — Entry Editor
- Display name input
- Keys input rendered as tag chips (removable pills); comma-separated value underneath
- Full textarea for entry content with live char/token counter
- `@type` and `@role` shown as badge selectors — click to cycle, updates metadata header automatically
- **Advanced settings** (collapsed by default): Search Range, Force Activation toggle, Budget Priority slider, Prefix, Suffix, Lore Bias — matching all NovelAI lorebook fields
- Save / Delete buttons
- New Entry button in panel header creates blank entry in selected category

### Proxy Usage
All operations use existing `loreCall()` proxy: `createEntry`, `updateEntry`, `removeEntry`, `createCategory`, `updateCategory`, `removeCategory`. No new proxy channels needed.

### Modified Files
- `app/renderer/modules/headless-lore-panel.js` — full rewrite
- `app/renderer/index.html` — updated panel HTML structure
- `app/renderer/modules/dom-refs.js` — updated refs

## Section 4: Preamble / Instructions Panel

### Concept
A new dedicated panel for preamble text and author's note, giving these complex documents the space they deserve. Replaces the orphaned textarea fields in the AI Settings panel.

### Panel Contents
- **Preamble** — Large textarea, upper half of panel. Text prepended before story content in the AI context. Live char/token counter. "What is this?" tooltip for discoverability. Templates dropdown with starter presets (Establish POV, Genre/tone setter, Writing style guide).
- **Author's Note (AI Instructions)** — Second textarea below a divider. Injected at configurable depth into context. Depth slider: 0–200 tokens from end, matching NovelAI's Author's Note control.
- **Save button** — Saves preamble to `story_settings.preamble` and pushes Author's Note via `memoryCall('setAuthorNote')`.

### Wiring
Preamble is stored in `story_settings.preamble` and loaded directly on story open — no memory field parsing needed. At generation time, preamble is prepended to the memory payload before it is written via `memoryCall('setMemory')`, separated by a blank line, so NovelAI receives the full assembled context.

Author's Note uses the existing `memoryCall('getAuthorNote')` / `memoryCall('setAuthorNote')` bridge — no new proxy channels needed.

### New Files
- `app/renderer/modules/headless-preamble.js` — panel logic, template system, load/save

### Modified Files
- `app/renderer/index.html` — new panel HTML, toolbar button
- `app/renderer/modules/headless-sync.js` — wire into init
- `app/renderer/modules/headless-memory-note.js` — remove Author's Note section (moved here)

## Section 5: Memory Management

### Concept
The single memory textarea is replaced with a three-section structured panel that maps to how writers actually use memory.

### Sections

**Pinned Facts**
A bullet-point list of always-true facts (protagonist name, setting, world rules) that are always prepended to assembled memory at full priority. Each bullet is a short editable line. Add / remove individual bullets.

**Narrative Memory**
Main textarea for what has happened recently. A "Summarise from story" button runs a `callLLM()` call against the last ~4000 characters of story text and drafts a summary for the writer to edit before saving.

**Context Preview** (collapsed by default)
Read-only expandable section showing the final assembled context — Preamble (read from `story_settings.preamble`) + Pinned Facts + Narrative Memory — with a token budget bar colour-coded by segment. Shows consumption against the model's context limit.

### Assembly
Sections concatenated: Pinned Facts → blank line → Narrative Memory. Written via `memoryCall('setMemory')`. On load, memory field is parsed back into sections by the same structure.

### Auto-save
Memory is automatically saved when switching stories or triggering generation.

### Modified Files
- `app/renderer/modules/headless-memory-note.js` — restructured; Author's Note UI moved to Preamble panel
- `app/renderer/index.html` — updated memory panel HTML
- `app/main.js` — `text-action` IPC handler (shared with AI text actions in Section 6); `type: 'summarise-memory'` variant
- `app/preload.js` — bridge method for above

## Section 6: General Polish

### Broken Pieces Fixed

**AI text actions (Rewrite, Expand, Summarize, Shorten)**
The current command injection approach (`[ Rewrite the following: ... ]`) is unreliable. Replaced with direct `callLLM()` calls via a new `text-action` IPC handler in `main.js` using `makeLoreGenerateTextFn()` (same provider selection logic as lore scanning — NovelAI text API or Ollama). Selected text sent directly; result replaces the selection in the editor. The same IPC handler also serves the "Summarise Memory" action (Section 5) with a `type` discriminator. No more dependency on NovelAI parsing an undocumented command format.

**History panel**
Reimplemented to reliably read snapshot items from the NovelAI webview using `executeJavaScript`. Restore operation clicks the correct DOM element and waits for confirmation before syncing. Removes hardcoded mock data fallback.

**Stop Sequences**
Wired up in the AI Settings panel. Read/write via React fiber traversal same as existing Temperature and Output Length fields.

### Navigation Improvements
- Panel open/close: 150ms slide-in from right (`transform: translateX` transition) — replacing instant toggle
- Toolbar reorganised: Memory + Preamble grouped as context tools; Lore + Active Lore as lore tools; `M/E/G` theme switcher near word count
- All panels: consistent header (title left, close button right) and footer (action buttons in a strip)

### New Keyboard Shortcuts
